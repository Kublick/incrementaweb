# Tailwind 3 → 4 Migration Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Migrate the project from Tailwind 3 + `@astrojs/tailwind` integration to Tailwind 4 + `@tailwindcss/vite` plugin, preserving all custom theme tokens and the existing visual output.

**Architecture:** Replace the Astro integration with the Vite plugin (per Astro 7's recommended Tailwind 4 path). Convert the JS config (`tailwind.config.cjs`) into a CSS-first `@theme` block in `src/styles/global.css`. Import that stylesheet from the root layout so every page gets the tokens. No source template files need to change — class names (`font-coolvetica`, `text-blue`, `bg-secondary`, etc.) will continue to work because the same names are generated by the new config.

**Tech Stack:** Astro 7.0.3, Tailwind CSS 4, `@tailwindcss/vite`, pnpm.

**Files:**

Expected:

## Task 3: Wire Vite plugin into Astro and import the global stylesheet

**Files:**
- Modify: `astro.config.mjs` (replace 8 lines)
- Modify: `src/layouts/Layout.astro` (add 1 import in frontmatter)

**Step 1: Update `astro.config.mjs`**

Replace the file contents with:

```js
import { defineConfig } from "astro/config";
import react from "@astrojs/react";
import tailwindcss from "@tailwindcss/vite";

// https://astro.build/config
export default defineConfig({
  integrations: [react()],
  vite: {
    plugins: [tailwindcss()],
  },
});
```

**Step 2: Import global CSS in the root layout**

In `src/layouts/Layout.astro`, at the very top of the frontmatter (before the existing `export interface Props` block), add:

```ts
import "../styles/global.css";
```

The resulting frontmatter should look like:

```ts
---
import "../styles/global.css";

export interface Props {
  title: string;
}
const { title } = Astro.props as Props;
---
```

**Step 3: Commit**

```bash
git add astro.config.mjs src/layouts/Layout.astro
git commit -m "feat(tailwind): wire @tailwindcss/vite and import global stylesheet"
```

## Notes

- The only custom classes actually used in templates (verified via grep) are: `font-coolvetica`, `font-inter`, `text-blue`, `text-purple`, `text-lightPurple`, `bg-secondary`, `border-secondary`, plus a few `text-white` and other defaults. All are covered by the `@theme` block.
- Tailwind v4's `space-*` selector change and renamed `shadow-*` / `ring-*` / `outline-*` scales are documented in https://tailwindcss.com/docs/upgrade-guide. None of the v3-specific deprecated utilities (`bg-opacity-*`, `flex-shrink-*`, `shadow-sm` intended as the "bare" scale, etc.) are used in this codebase, so no template edits are required.
- `prettier-plugin-tailwindcss@^0.6.9` already supports Tailwind v4 — no change needed.
